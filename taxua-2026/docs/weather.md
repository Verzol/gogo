# Sky opening and trip-day weather

## Owners

- `TRIP_DATA.weather` in `data.js`: destination coordinates, Vietnam timezone and interface copy. Dates come from `TRIP_DATA.days`, beginning with the day containing `arrival`; currently 23–25 October 2026.
- `scenery.js`: opening clouds, continuous cloud tracks, measured altitude progression, weather accents and image-decode guard. `JourneyScenery.openingBounds()` supplies the story handoff boundary to both scene controllers.
- `weather.js`: optional classic script after `motion.js`; daily request, cache, null handling, WMO interpretation, input and motion preference.
- `weather.css`: hero grid, concise forecast, sticker float and rain/snow. The precipitation fields are outside `#sceneLayers`, so navigation snapshots cannot duplicate them. The scene container is isolated at stack level 0 and precipitation sits at level 1, above all sky artwork and below page content.
- `scripts/prepare_illustrated_scenery.py`: original import and desktop/phone alpha derivatives. `data/sources/illustrated-scenery.json` records upload names, hashes, dimensions and outputs.

The six base worlds, chapter phase, itinerary date links and story stickers retain their existing owners. Weather never changes those values. The opening uses its own native-scroll listener, shared measurements and independent depth wrappers, so altitude also updates during anchor travel and the GSAP scrub never delays the physical descent.

## Opening and controls

The hero starts in a pale blue/jade sky framed by five supplied watercolor cloud designs. Four load initially; the overcast cluster decodes on first relevant preview. Near clouds part upward/outward while distant clouds move less. Terrain starts rising after the lowest hero content is above the lower quarter of the screen. The night dissolve waits until the copy, forecast and clock clear the top reading lane. There is no extra spacer, pin or persistent cloud bank.

The forecast and compact clock occupy a real summary column on desktop and normal flow on phones. The panel keeps daily conditions, temperatures, precipitation probability, selected-day wind/gusts and a saved-forecast indicator when needed. Update timestamps and provider/license links are omitted from the front-page panel; source references remain in the documentation. Hover instructions and explanatory paragraphs are omitted. One compact status/action row reserves space for selected-day wind, saved-data status and reset/retry without the old separate empty footer. The three native date buttons preview on pointer hover or keyboard focus. Enter/Space or tap holds/toggles a date; “Trời ban đầu” and Escape clear it. Leaving the hero or following an enhanced anchor clears the preview. Rapid switches cancel stale cloud-decode completions. Preview interactions make no requests and never change the URL hash.

The 44px pause/play icon beside the forecast heading pauses decorative clouds, the coffee sticker and precipitation, retaining their pose. Its tooltip and screen-reader label identify the current action; reduced motion disables it with an explanatory accessible name. Its preference is saved when storage is available. Hidden tabs pause decoration. Cloud motion uses linear Web Animations on the inner image’s `translate`, independent of scroll transforms. Desktop near clouds travel at 17–26 CSS px/s in calm weather, distant clouds at 8–13 px/s; story puffs/wisps at 10/6 px/s. Desktop tracks retain three evenly spaced copies and broad overlapping coverage. Each track spans the viewport plus the cloud's full width and a parallax margin; individual copies recycle fully offscreen. Copies reuse local artwork and decode cache, retain their scene stacking order, and appear in pause and frozen navigation poses. No spawning timer or growing element pool is used. Wind changes update playback rate without restarting the track; resizing remeasures bounds while retaining the current offset. Inactive story panels and the departed opening pause their cloud tracks. Navigation clones freeze the actual computed pose. Reduced motion pauses cloud tracks and removes sticker/particle animation and descent parallax; missing GSAP uses the native scene fallback without descent parallax. Forecast information remains usable. Print omits weather and scenery; the standalone reading copy contains no live forecast.

### Mobile composition

Phones up to 767px wide and landscape screens up to 520px high use three opening lanes: one high cloud, two near-side copies and two distant copies. The other lanes and opaque overcast artwork are hidden; their animations are cancelled and repeated elements removed. Near/distant artwork masks soften the middle of the viewport without changing the sky itself. The high cloud frames the top. Base speeds are 10/15/8 CSS px/s, scaled from 0.85–1.1 by viewport width. Mobile cloud/precipitation speed caps at 2.4× under strong wind, while desktop retains 3.8×. Rain severity, snow, cold tint and fog remain independent of that density reduction.

Mobile opening spacing is tighter, supporting forecast text is at least 12px at the default root size, and temperature/title lines can wrap under text enlargement. The countdown follows the forecast in natural flow. The mobile cloud acceptance is steady replenishment with a five-sprite pool and a clear reading region, replacing the older minimum-six/full-width cloud requirement; desktop keeps its previous coverage check. See the [mobile audit and implementation plan](mobile-ui-plan.md).

## Data and unavailable states

The optional Open-Meteo request uses the regional pin **21.27516 N, 104.43396 E** and `Asia/Ho_Chi_Minh`, with automatic model elevation. No visitor location, API key, SDK or backend is required. Artwork, fonts and libraries remain local; forecasts require network access. The regional label identifies this as an area forecast rather than exact lookout conditions.

Requested daily fields: weather code; minimum/maximum temperature; minimum apparent temperature; maximum precipitation probability; precipitation and snowfall totals; maximum wind and gusts. Temperatures are Celsius, wind km/h. The daily code describes the day's most severe condition. Sky previews illustrate that daily summary; they are not hourly observations.

The request includes only trip dates between today's Vietnam date and today +15 days. Dates outside the horizon stay visible and inactive; elapsed dates read “Ngày đã qua”. An open page rechecks eligibility at Vietnam midnight, without polling or fetching on hover. After the trip there is no unrelated rolling request. Null temperatures remain dashes. Unknown codes use a neutral cloudy image and explicit unknown label. Missing days remain independently unavailable.

One versioned cache key includes the pin, timezone, fields and trip dates. Fetch once per hour, refresh on a new visit or return to a visible tab when expired, and offer retry after failure with a 15-second cooldown. Requests abort after eight seconds and validate HTTP status, dates and array shapes. Storage failure falls back to memory. After refresh failure, a forecast up to 24 hours old can remain with a saved-data indicator; older or corrupt cache is discarded. Client retrieval timestamps remain internal to cache management; expired cached data reads “Dự báo đã lưu” without a timestamp. Provider and license references remain in [Sources](sources.md#sky-and-weather-ui-research-15-october-2026).

Clear/partly cloudy/overcast/fog/drizzle/rain/freezing rain/snow/thunderstorm codes get separate labels and suitable sky/cloud treatments. Temperature adds an independent cool tint. Daily wind maximum and gust excess scale cloud playback from 1× to 3.8×, and tilt/accelerate precipitation. This is a steady illustration of the daily wind summary, not a simulated live gust reading. Rain/snow use small local vector tiles. Drizzle (51–57) has fine short strokes, light rain longer strokes, moderate/heavy rain progressively faster and stronger fields, and storms the densest field. Snow codes distinguish light/heavy flake opacity. Both precipitation depth layers travel exactly one repeated tile height, avoiding a visible loop reset. Cold alone and rime fog never produce flakes. Snow requires a snow code or positive snowfall when the code is missing. Storms have rain and heavier clouds without lightning flashes. No snow-covered terrain is inferred.

## Artwork and verification

The five originals are now `cloud_hero_left.png`, `cloud_hero_right.png`, `cloud_sea_far.png`, `cloud_transition_near.png` and `cloud_overcast.png` under `figures/raw/illustrated_scenery/`. Original pixels and transparency are preserved. Runtime WebP derivatives are only downsampled. Initial cloud files total approximately **121 KiB on phones / 356 KiB on desktop**, excluding existing scenery; overcast is deferred. These are encoded file sizes, not a claim about total page transfer or device performance.

Run `node scripts/verify_weather.cjs`. It intercepts forecasts with a running test clock, so clear/cold/rain/snow and unavailable states do not depend on live weather. Checks include icon placement/accessibility, fifteen minutes of sampled desktop/phone cloud replenishment with a bounded pool, measured cloud movement, offscreen recycling, wind rate changes without position jumps, actual painted drizzle pixels, severity differences and held pause poses. Evidence goes to `review/sky-weather/`; override with `WEATHER_REVIEW_DIR`. Existing journey, scenery, motion, reveals and countdown helpers accept `TRIP_REVIEW_DIR` to preserve historical evidence. See [verification](verification.md) for regression commands and device coverage limits.
